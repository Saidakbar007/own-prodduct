# Решения, принятые самостоятельно (автономный режим)

- Защита страниц: единая зависимость `require_user` в `app/auth.py` — если нет сессии, отдаёт 303 редирект на `/login`.
- Регистрация создаёт сразу 3 записи: `registration` (с хешем пароля), `users` (профиль) и `level` (точка отсчёта 0 очков) — иначе у нового пользователя не было бы уровня для начисления очков.
- Все datetime-поля хранятся как timezone-aware (UTC) — новая версия SQLAlchemy/SQLModel требует это для корректной сериализации, `datetime.utcnow()` без таймзоны выдавал ошибку.
- Streak считается от последней фактической отметки назад по дням подряд; если последняя отметка была более суток назад — streak = 0. Если сегодня ещё не отмечено, но вчера было — streak не сбрасывается мгновенно.
- "Streak друга" (для страницы друзей) = наибольший текущий streak среди всех привычек этого пользователя (а не отдельно по каждой привычке).
- Мечта хранится как запись в таблице `goals` с `parent_id = None`; обычные цели — с `parent_id` = id мечты. Счётчик `users.goals` увеличивается при создании и мечты, и цели (это одна таблица).
- Программы (Training/Education) создаются через отдельный роутер `app/routers/programs.py`, но отображаются на странице цели (`app/routers/goals.py` → `goal_detail`), т.к. визуально относятся к одной цели.
- AI-коуч по умолчанию — заглушка на основе простых правил (нет привычек / нет серии / серия ≥ 7 дней). Если в `.env` задан `ANTHROPIC_API_KEY`, используется реальный вызов Claude API (`claude-haiku-4-5-20251001`); при любой ошибке API — тихий откат на заглушку, чтобы страница коуча не падала.
- `bcrypt` зафиксирован на версии `4.0.1` по прямому указанию пользователя (несовместимость `passlib` с `bcrypt` 5.x).
- Дедлайны на дашборде главной: показываются только незавершённые цели с заданным дедлайном, ближайшие 5, по возрастанию даты.

## v2 (после тега v1-mvp)

- Очки по сложности считает сервер: `point`/`story_point` остались в схеме БД (не убирал поля из таблиц), но форма отдаёт только `difficulty` (easy/medium/hard) → сервер сам ставит `point` (5/10/20 для привычки, 50/100/200 для цели) и всегда `story_point=1.0`. Клиент очки не присылает.
- Схема БД расширена сверх исходной ER-диаграммы (это явный запрос пользователя, не домыслы): `habits.habit_type`, `habits.frequency`, `habits.weekdays` — для типа и частоты привычки; новые таблицы `goal_steps`, `achievements`, `user_achievements`, `daily_tasks`, `points_log`, `coach_messages`.
- "День без срыва" для вредной привычки технически — та же механика отметки (1 раз в день, антиобман не менялся), отличается только текст кнопки и иконка.
- Частота `weekly` хранит дни недели как CSV строку (`"0,2,4"`, 0=понедельник) — простое решение без отдельной таблицы, т.к. это просто фильтр для раздела "привычки на сегодня".
- Прогресс цели = доля выполненных шагов (`goal_steps`); у цели без шагов прогресс 0%, у завершённой — всегда 100%. Прогресс мечты = среднее арифметическое прогресса её целей (0%, если целей нет).
- Ежедневные задания: пользователь сам отмечает выполнение кнопкой «Выполнено», без автоматической проверки реального действия — проще и прозрачнее для MVP, чем отслеживать условия задания по логам.
- Недельный рейтинг друзей считается по новому журналу `points_log` (у каждого начисления очков есть метка времени) — суммы за 7 дней, а не общий счёт за всё время.
- Всплывающие уведомления (очки/уровень/достижения) хранятся в cookie-сессии как одноразовая очередь: показались на следующей отрисовке страницы — очистились.
- `app/rendering.py` — общий `render()` вместо прямого `templates.TemplateResponse` во всех роутерах: один раз добавляет XP-бар в шапку и flash-уведомления, чтобы не повторять эту логику в каждом роуте.
- AI-коуч теперь хранит историю переписки (`coach_messages`); при первом визите страница сама создаёт приветственное сообщение коуча.
- `app/database.py`: путь к БД можно переопределить переменной `DATABASE_URL` — понадобилось, чтобы проверить новую схему v2 на отдельной временной базе, не трогая уже работающий `app.db` (на нём был запущен сервер пользователя, а SQLModel не делает миграций — новые колонки не добавляются в существующие таблицы автоматически).
- **Важно для пользователя:** старый `app.db` (созданный до v2) несовместим с новой схемой — перед использованием v2 его нужно удалить (сервер создаст новый при следующем запуске) и заново прогнать `python seed.py`.
- Мобильная адаптивность (375px) проверена вручную по классам Tailwind (mobile-first: `grid-cols-1`/`grid-cols-2` по умолчанию, `sm:` для широких экранов; навигация — горизонтальный скролл), а не живым браузером: инструменты браузера в этой сессии не могут открыть `localhost`-сервер, который запускает сам Claude, а установка Playwright только для одной проверки не оправдана по затратам.
- Коммит v2 сделан одним коммитом, а не по шагам 1-8 отдельно: с первых минут код оказался взаимосвязан (XP-бар и уведомления затрагивают все роуты, достижения проверяются из habits/goals/friends сразу) — разрезать на отдельные коммиты означало бы либо ломать промежуточные состояния, либо искусственно переписывать историю. Тесты и проверка сервера запускались для всего v2 целиком (56/56 тестов, все страницы вручную проверены на изолированной БД) перед коммитом.
