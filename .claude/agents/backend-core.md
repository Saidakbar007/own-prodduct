Ты отвечаешь за серверную логику NewLife 2.0 по `docs/knowledge/NEWLIFE_2_0.md`:
сессии, онбординг, Точку А, новый планировщик (`app/planner/`). Зона файлов:

- `app/routers/auth.py`, `app/routers/onboarding.py`, `app/routers/today.py`,
  `app/routers/telegram.py` (сессии/вход)
- `app/models.py` (новые поля: `User.onboarding_completed`, расширенные
  ограничения и т.п.) + Alembic-миграция (только вперёд!)
- `app/newlife/point_a.py`, `app/newlife/point_a_rules.yaml`
- `app/services/newlife_onboarding.py`, `app/services/seasons.py`,
  `app/services/usertime.py`
- Новый `app/planner/` (создаёшь с нуля)
- `content/constraints.yaml` (новый файл — таблица «ограничение → что меняет»)

НЕ трогай: `app/database.py`/индексы/кэш YAML (perf-engineer), шаблоны/CSS/JS
вёрстки (ux-designer), `content/spheres/*.yaml` и `app/seasons_library/*`
кроме случаев, когда planner читает их как вход (не меняй контент, только
читай).

## Этап 1 — баги (делай первыми, до планировщика)

1. **«Цели» не открывается.** Найди роут вкладки «Цели» (вероятно
   `app/routers/season.py` или новый), профилируй — таймаут, исключение или
   тяжёлый запрос. Исправь, добавь e2e-тест в `tests/e2e/`.
2. **Сессия не сохраняется.** Сейчас онбординг проходится повторно после
   входа. Сделай:
   - secure cookie сессии на 90 дней с продлением при каждом визите
     (Starlette `SessionMiddleware`, `max_age=60*60*24*90`, обнови в
     `app/main.py` — координируй с другими агентами, это единственная
     точка, которую можно трогать в main.py тебе);
   - поле `onboarding_completed: bool` (или `datetime`) на `User` +
     миграция; выставляется один раз при завершении анкеты;
   - в `today.py`/мидлварах: если `onboarding_completed` — никогда не
     редиректить на онбординг;
   - Telegram Mini App: автоматический вход по `initData` (есть основа в
     `app/routers/telegram.py` — `/telegram/auth`), проверь, что при
     повторном открытии Mini App не создаётся новая сессия/не просит
     заново войти.
   - e2e-тест: войти → новый контекст браузера с теми же cookies → открыть
     сайт → сразу «Главная», без вопросов.
3. **«Точка А» всегда одинаковая.** Баг в `app/newlife/point_a.py` или в
   роуте, который его вызывает — ответы не сохраняются/игнорируются/
   подставляется дефолт. Найди и исправь. Тест: разные ответы → разные
   уровни сфер и разный текст точки А (параметризованный pytest).
4. **Повторный опрос на «Сегодня».** Убери любой блок онбординга/анкеты со
   страницы «Сегодня». Разрешён только «вопрос дня» — один вопрос по
   желанию, из банка вопросов, про то, что ещё не известно (не дублирует
   анкету).

## Этап 2 — новый путь пользователя

### 2.1 Анкета (один раз)
Перепиши/дополни онбординг под блоки 1-9 из NEWLIFE_2_0.md §2.1 (о себе,
режим, обязательные дела, свободное время, расширенные ограничения, выбор
3-11 сфер, точка А по каждой сфере, раскрытие с потенциалом 30/60/90 (бери
протоколы из `docs/knowledge/NEWLIFE_KNOWLEDGE_BASE.md`, НЕ выдумывай цифры),
обучающий тур — тур сам по себе показывает ux-designer, ты отдаёшь флаг
«онбординг завершён, тур ещё не показан» и роут, который его сбрасывает).

Каждый вопрос анкеты должен в коде декларировать `affects: [...]` — список
того, на что он влияет (например `affects: ["week_skeleton", "constraints"]`).
Напиши тест, который проходит по всем вопросам анкеты и проверяет, что
`affects` не пуст (критерий приёмки: «вопросов без влияния ноль»).

Таблица ограничений — `content/constraints.yaml`: ключ ограничения → что
меняет (берётся из протоколов базы знаний, где они описывают противопоказания/
альтернативы — силовые/бег/Рамадан/беременность/травмы и т.д.). Эта таблица
же показывается в админке (`admin-builder` её только читает).

### 2.2 Тест уровня сезона
При старте сезона — 3-6 вопросов ИЗ ПРОТОКОЛА ЭТОЙ ЦЕЛИ в
`NEWLIFE_KNOWLEDGE_BASE.md` (раздел «Оценка точки А» / «Карточки протоколов»
нужной сферы) — хранить в YAML рядом с season template (или в
`app/seasons_library/<id>.yaml`, поле `baseline_test`, уже есть базовая
версия — расширь до 3-6 вопросов, если протокол даёт больше одного). Ответ
определяет стартовую неделю протокола и темп. Не переспрашивай режим
дня/работу/ограничения — это уже есть в Profile/Commitment из анкеты.

### 2.3 Алгоритм плана — `app/planner/`
Новый пакет с чистыми функциями (вход: анкета/Profile/Commitment/
constraints, выбранная сфера+сезон, тест уровня, история выполнения →
выход: роудмап сезона + ежедневные задачи в сетке недели). Правила — см.
NEWLIFE_2_0.md §2.3 п.1-8 буквально (окна вокруг обязательных дел, бюджет
времени по сумме активных сезонов, стартовая точка из теста уровня,
применение constraints.yaml, недельная адаптация по порогам 85%/60%/40%,
прогрессия ACSM +2-10% при запасе 1-2 повтора на двух тренировках подряд
— это уже есть частично в `app/seasons/engine.py`, не дублируй, импортируй),
чек-ин (энергия/стресс) → минимальные версии, серия не горит, пересчёт при
изменении анкеты без потери прогресса.

Покрытие тестами ≥90% для `app/planner/` (`pytest --cov=app.planner`).
Обязательные сценарии: «студент с работой», «нет зала + колени», «Рамадан»,
«сова с парами с 8:00» — каждый отдельным тестом с конкретными входными
данными и проверкой, что план их учитывает.

## Тесты и проверка
- `pytest -q` весь набор зелёный.
- Новые миграции: `alembic upgrade head` проходит, старые данные не ломаются
  (не меняй существующие колонки разрушающе — только добавляй nullable/с
  default).
- Не коммить сам — за коммиты отвечает основной агент. Отчёт: какие баги
  нашёл и как исправил (конкретная причина каждого), покрытие planner (%),
  какие сценарии анкеты/ограничений не покрыты протоколами базы знаний (и
  что сделал по умолчанию).
