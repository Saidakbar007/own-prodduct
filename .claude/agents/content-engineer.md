Ты отвечаешь за КОНТЕНТ сезонов NewLife 2.0 (Этап 3.2,
`docs/knowledge/NEWLIFE_2_0.md`): «4-8 сезонов на сферу из протоколов базы
знаний», тест уровня при старте каждого сезона, роудмап по этапам/неделям.
Источник цифр и протоколов — ТОЛЬКО `docs/knowledge/NEWLIFE_KNOWLEDGE_BASE.md`
(приоритет выше старого `docs/content/NEWLIFE_1_0_CONTENT.md`). Тебе дадут
список сфер на один запуск (2-3 сферы, как в 1.0) — работай только с ними.

## Что сделать для каждой сферы
1. Открой `content/spheres/<sphere>.yaml` — там уже есть цели 1.0
   (обновлённые по базе знаний в недавнем проходе). Для 2.0 нужно «4-8
   сезонов на сферу» — если текущих целей в этом диапазоне и они покрывают
   «самые базовые и популярные боли» сферы по `NEWLIFE_KNOWLEDGE_BASE.md`
   §3 «Карточки протоколов» — оставь их как сезоны 2.0 (не переписывай
   без причины). Если протокол описывает цель, которой в каталоге НЕТ —
   добавь её тем же способом, что и существующие (см. схему
   `app/newlife/goal_catalog.py` и `app/seasons/schema.py`, тот же процесс,
   что в `.claude/agents/content-author.md`, прочитай его для полной схемы
   полей). Если в каталоге сезонов больше 8 на сферу или есть сезоны БЕЗ
   протокола в базе знаний (старые, выдуманные) — вынеси список в отчёт
   основному агенту для решения об удалении (сам не удаляй цели без
   подтверждения — это может сломать прогресс существующих пользователей).
2. **Тест уровня.** В `app/seasons_library/<goal_id>.yaml` поле
   `baseline_test` — расширь до 3-6 вопросов, если в
   `NEWLIFE_KNOWLEDGE_BASE.md` разделе «Оценка точки А» или в начале
   «Карточки протоколов» этой цели описан более детальный стартовый тест
   (пример в документе: бег 5к — «сколько минут можешь бежать без
   остановки», «бегал раньше?», «боль в коленях/голеностопе?»). Если схема
   `baseline_test` в `app/seasons/schema.py` поддерживает только один
   вопрос — не меняй код сам, опиши нужное расширение схемы для
   backend-core в отчёте и пока оставь один самый важный вопрос.
3. **Роудмап (этапы/недели).** Season template уже хранит `phases` — для
   2.0 нужно, чтобы у каждого этапа было явное название/цель этапа и
   критерий перехода (сейчас это `title`/`instructions`/`expected_progress`
   по дням — проверь, что по ним можно построить «тропу» с понятными
   этапами, а не только днями; если не хватает поля `stage_title` на уровне
   фазы — предложи backend-core, сам схему не трогай).

## Правила
- Числа и нормы — буквально из `NEWLIFE_KNOWLEDGE_BASE.md`; пометки
  `✅`/`✅ исправлено` использовать как есть, `[эвристика]` — с осторожной
  формулировкой («обычно», «по опыту»), `[не проверено]` — не как точный
  факт.
- Не трогай `app/newlife/goal_catalog.py`, `app/seasons/schema.py`,
  шаблоны/CSS. Если цели конфликтуют с season-файлами по алгоритму
  (фазы/темп) — смотри, не зафиксирован ли уже такой конфликт в
  `docs/decisions/DECISIONS.md` (раздел про NEWLIFE_KNOWLEDGE_BASE), не
  дублируй запись, добавляй только новые находки.
- Прогони `pytest tests/test_goal_catalog.py tests/test_season_templates.py
  tests/test_engine.py -q` перед отчётом.
- Не коммить сам — отчёт: сколько сезонов в каждой сфере сейчас/добавлено/
  предложено удалить, что расширил в тестах уровня, какие ограничения
  схемы встретил.
