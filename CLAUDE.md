# NewLife

Бесплатное приложение саморазвития для студентов 18–25 в Узбекистане:
знакомство кнопками → точка А по 11 сферам жизни → 1–3 цели → расписание
недели вокруг учёбы/работы/сна → ежедневные действия, привычки, сезоны
30/60/90 дней с финальным Reveal «до → после». Только алгоритмы, без ИИ.

## Источники правды (по приоритету)

1. **`docs/product/PRD_1.0.md`** — что делаем. «Критерии приёмки 1.0» =
   определение «готово». «Вне объёма» — запрещено реализовывать.
2. **`docs/content/NEWLIFE_1_0_CONTENT.md`** — контент всех 11 сфер; его
   поправки норм Тела важнее старой спеки.
3. **`docs/product/BRD_1.0.md`** — зачем и для кого.
4. `docs/specs/NEWLIFE_V8_SPEC.md`, `docs/specs/SEASONS_SPEC.md`,
   `docs/design/DESIGN.md`, `docs/decisions/DECISIONS.md` — всё, что не
   противоречит пп. 1–3; история решений и алгоритмов с версии v8/Сезоны.
5. `docs/START_1.0.md` — исходный рабочий промт (этапы сборки 1.0).

Текущий прогресс по этапам 1.0 и чек-лист — `docs/RELEASE_1.0_PROGRESS.md`.

## Стек

Python 3.12, FastAPI, SQLModel, Alembic, Jinja2 + HTMX, PostgreSQL (Neon) /
SQLite, Render (хостинг), Telegram Bot API (Mini App + напоминания).

## Как запустить локально

```
pip install -r requirements.txt
cp .env.example .env   # заполнить SECRET_KEY; DATABASE_URL пустой = SQLite
uvicorn app.main:app --reload
```
Открыть http://127.0.0.1:8000. Демо-данные: `python scripts/seed_demo.py`.

## Как тестировать

```
pytest                      # unit
pytest tests/e2e            # Playwright e2e (375px, светлая/тёмная тема)
```
Полный прогон (pytest + e2e) — в конце каждого этапа/фазы, не после каждого
шага. Скриншоты e2e — в `docs/design/design_review/`.

## Правила работы

- Работай сам, без лишних вопросов; неоднозначности решай разумно и
  записывай в `docs/decisions/DECISIONS.md`.
- Коммит после каждого рабочего шага. После шага — только связанные тесты;
  полный набор — в конце этапа.
- Каждый экран — e2e на 375px, в светлой и тёмной теме, на обоих языках
  (ru/uz), когда каталоги на узбекском готовы.
- Только кнопки, ни одного обязательного текстового поля. Никакого ИИ в
  продукте (см. «Вне объёма» в PRD). Один движок — много контента: новая
  цель/привычка добавляется YAML-каталогом, без нового кода.
- Не создавай новых файлов в корне репозитория сверх перечисленных выше;
  отчёты и прогресс — в `docs/`.
- Не печатай секреты и не коммить `.env`. Миграции только вперёд, данные
  существующих пользователей не ломать.
- В конце этапа/фазы: слить в `master`, пуш, проверить деплой на Render,
  короткий отчёт и список того, что сделать вручную (Neon, токены,
  переменные Render — сам не выполняй).
